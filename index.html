RSS-Atom-CLI

Reading feeds in the terminal, printed off the tape. rss_tool.py reads RSS 2.0 and Atom feeds, accepts feed URLs or local files, and prints numbered items with dates and links. One Python file, standard library only, nothing to install.

Open the repo When feeds fail

- - - - - -

The fetch

Anything that starts with http is fetched with a 20 second timeout and a User-Agent of RSS-Atom-CLI/1.0, so a dead host cannot hang the run and the feed server can see what asked. Everything else is opened as a local file. Both paths hand the same bytes to the parser.

- - - - - -

The parse

The root tag tells Atom from RSS. Atom items take the alternate link over the self and edit links, and prefer the updated time over the published time. A file that is neither format raises an error instead of printing an empty list.

- - - - - -

The listing

The feed title opens the listing, then numbered items follow, sliced by --limit, which defaults to 10, with dates shortened to a clean day. --open N reprints one chosen link on its own line at the foot of the listing, the line the repo README describes; asking past the end prints how many items the feed holds instead of failing.

python3 rss_tool.py https://example.org/feed.xml
python3 rss_tool.py feed1.xml feed2.xml --limit 5
python3 rss_tool.py https://blog.example.org/rss --open 2

- - - - - -

When feeds fail

Several feeds may ride in one command. One bad feed prints its error and the run continues with the rest; the exit code is non-zero only when every feed failed, so a script can trust the signal. A feed tool the repo README links alongside the CLI is Feedly, recorded here as it stands in the repo README.

RSS-Atom-CLI keeps the old discipline of the tape: fetch, parse, print, and let one broken feed stop nothing.
