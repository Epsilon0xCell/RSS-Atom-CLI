Dispatch 02, what it does

I hand it a feed. It hands back a listing.

I wrote this because I wanted to read feeds without opening a browser or installing a package first. I give rss_tool.py one or more feed URLs, or local feed files, and it prints the items with titles, dates, and links, numbered from 1.

It tells the two formats apart in parse(). If the root tag ends in feed, it reads Atom entries. Otherwise it looks for an RSS channel and walks its items. For Atom I take the first link with no rel or with rel alternate, because that is the article link. The self and edit links point at the feed machinery, and I skip them on purpose.

Fetching is plain about its split too. In fetch(), a source that starts with http goes out through urllib with my own user agent, RSS-Atom-CLI/1.0, and a 20 second timeout. Anything else is read as a local file, as bytes, same as the remote path returns.

Dispatch 04, the --open rule

--open prints a link. It does not open anything.

The module docstring promised --open for a long time before the code had it. It has it now, and I checked this page against the code at head before I filed it. The flag checks the number against the full item list, not the limited slice shown above it, so I can ask for a link past the limit I set for the listing. Out of range, it tells me how many items the feed has and the run still counts as a success.

It does not launch a browser. That part is a choice, not a gap. I use this over SSH and in scripts, where there may be no browser at all, and a bare URL on its own line is the thing a caller can actually use.

Dispatch 05, dates

Two date shapes come in. I handle one and I cut the other honestly.

Atom dates use the ISO shape, so I swap a trailing Z for +00:00, parse with fromisoformat, and print a short year, month, and day. RSS pubDate uses the RFC 822 shape, which fromisoformat cannot read. When that parse fails, I print the first 16 characters of the raw date. That slice holds the weekday and the date, as the run in Dispatch 03 shows. I would rather show part of a date than drop the date and leave a reader guessing.

Code capture: rss_tool.py, lines 114 to 125 at head 72696fc.

114     for i, item in enumerate(items[:limit], 1):
115         date = item["date"]
116         try:
117             # I swap a trailing Z for an offset that fromisoformat can
118             # read. Atom dates use that Z form a lot.
119             date = datetime.fromisoformat(date.replace("Z", "+00:00")).strftime("%Y-%m-%d")
120         except ValueError:
121             # RSS pubDate uses the RFC 822 shape, which fromisoformat
122             # cannot read. I show the first 16 characters instead,
123             # because that slice is the weekday and the date, and I
124             # would rather show part of the date than drop it.
125             date = date[:16]

Dispatch 08, honest notes

What I will not dress up

This is a small tool and the page should not pretend otherwise. One file, two feed formats, a limit flag, and an open flag that prints a link. There is no database, no saved state, no unread tracking, and no refresh on a timer. I run it, I read the listing, and it ends.

Failure handling is the one piece I took care with. I catch errors per feed and keep going, because the feeds in a multi feed run do not depend on each other. The run returns 1 only when every feed failed. A feed file I do not understand raises a plain error, not an RSS or Atom feed, instead of printing an empty listing that would look like a feed with no posts.
